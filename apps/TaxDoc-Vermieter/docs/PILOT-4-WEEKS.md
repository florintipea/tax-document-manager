# TaxDoc-Vermieter — 4-Wochen-Pilot

**Zielgruppe:** Privatvermieter, Haus-und-Grund-Mitglieder  
**Produkt-CTA / Beta:** https://taxdoc-beta.onrender.com  
**Track:** parallel zu TaxDoc (Haupt-App) — kein Rewrite

## Prinzipien

1. **Hilfsmittel** — keine Steuerberatung (§ 5 StBerG).
2. **Keine automatische ELSTER-Abgabe** — Nutzer prüft und reicht selbst / über Berater ein.
3. **2 in 1** — ein GitHub-Account, zwei Apps: TaxDoc + TaxDoc-Vermieter.

## Woche 1 — Onboarding

| Tag | Aktivität | Erfolg |
|-----|-----------|--------|
| 1–2 | Pilot-Partner briefen, Zugänge (Beta) | ≥ 5 Zusagen |
| 3–4 | Erste Objekte + Belege hochladen | ≥ 1 Objekt / Nutzer |
| 5–7 | Labels klären (Miete, Hausgeld, Reparatur) | Feedback-Notiz |

## Woche 2 — Anlage-V-Fokus

- Einnahmen vs. Werbungskosten zuordnen (Vorschläge, nicht verbindlich).
- Vermieter/Mieter-Heuristik aus TaxDoc nutzen, ohne Haupt-Landing umzubauen.
- Check: Disclaimer sichtbar auf Landing + /legal.

## Woche 3 — Partner-Feedback

- Strukturiertes 30-Min-Interview (Haus-und-Grund / Privatvermieter).
- Pain Points → Backlog (nur Vermieter-Track).
- FounderBlocks: Delay-Mail senden, falls Demo/Deadline rutscht (`FOUNDERBLOCKS-DELAY-EMAIL.md`).

## Woche 4 — Entscheidung

**Metriken (Leading):**

- Aktivierung (Login + ≥ 1 Upload)
- Belege pro Objekt
- Qualitative NPS-light (1 Frage)

**Go/No-Go:**

- Go: eigene Render-URL `taxdoc-vermieter` live, Soft-Door `/vermieter` auf TaxDoc belassen.
- No-Go / Pause: Landing + Docs bleiben; Product-Arbeit nur in TaxDoc Beta.

## Nicht im Scope dieses Pilots

- Steuerberatung / verbindliche Auskunft
- Auto-Submit an ELSTER
- Umbau der TaxDoc-Hauptpositionierung (Grenzgänger, Masse, etc.)
